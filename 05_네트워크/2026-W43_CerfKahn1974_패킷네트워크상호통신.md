## 한 줄 요약
**서로 다른 패킷 네트워크들을 '게이트웨이'로 연결하고, 종단 호스트끼리 신뢰성 있게 통신하는 공통 프로토콜(TCP)을 제안 — 오늘날 인터넷 구조의 설계도.**

## 왜 중요한가
두 저자는 이 논문으로 2004년 튜링상을 받았습니다. AI 공부와도 연결됩니다: 거대 모델의 **분산 학습**, 클라우드 추론, 연합학습(federated learning)은 모두 이 논문이 정한 "종단 간(end-to-end)" 원칙 위에서 작동합니다.

## 핵심 내용

### 1. 문제: 이질적인 네트워크
각 네트워크마다 패킷 크기, 속도, 오류율, 주소 체계가 다름. 이를 **하나로 통일하지 않고** 연결하려면?

### 2. 핵심 설계 원칙
| 원칙 | 설명 |
|---|---|
| **게이트웨이** | 네트워크 사이에서 패킷을 전달(필요시 분할)만 함 — 내부는 단순하게 |
| **종단 간 신뢰성** | 오류 복구·순서 보장은 네트워크가 아닌 **양 끝 호스트의 TCP**가 책임 |
| **계층적 주소** | 네트워크 번호 + 호스트 번호 → 오늘날 IP 주소의 원형 |
| **분할(fragmentation)** | 작은 패킷만 허용하는 네트워크를 지날 때 쪼개고 목적지에서 재조립 |

### 3. 신뢰성 메커니즘
- **순서 번호(sequence number)**: 바이트 단위로 번호를 붙여 순서 복원·중복 제거
- **확인 응답(ACK)과 재전송**: 일정 시간 내 ACK가 없으면 다시 보냄
- **슬라이딩 윈도우 흐름 제어**: 수신자가 받을 수 있는 양(윈도우)만큼만 전송

> 💡 수학적 관점: 슬라이딩 윈도우의 처리량은 대략 $\text{처리량} \approx \dfrac{\text{윈도우 크기}}{\text{왕복 시간(RTT)}}$ — 간단한 모델이지만 네트워크 성능 분석의 기본.

### 4. 연결 설정과 해제
양쪽이 초기 순서 번호를 맞추는 절차를 논의 → 이후 **3-way handshake**로 정착.

## 용어 정리
| 영어 | 한국어 |
|---|---|
| gateway | 게이트웨이 (현재의 라우터) |
| fragmentation / reassembly | 분할 / 재조립 |
| sequence number | 순서 번호 |
| acknowledgment (ACK) | 확인 응답 |
| sliding window | 슬라이딩 윈도우 |
| end-to-end principle | 종단 간 원칙 |
